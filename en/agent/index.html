How the AI assistant is built

The “Ask me” button on this site opens an assistant that answers questions about my profile and acts on the page itself. I designed and built it. Here I explain how it works, the decisions I made and where its limits are.

View the code

What it does and does not do

It does

  • Answer questions about my background, projects and skills, in Spanish or English.
  • Act on the page when you ask: take you to a section, filter the skills, switch language, download the CV or prepare the contact form.
  • Say it doesn't know when a fact is not on the site.

It does not

  • Send the form. It leaves it filled in for you to review and send yourself.
  • Give details about my work at SGS beyond what is already public here.
  • Discuss other topics or change role, even when asked to.
  • Get everything right: it is an AI and can be wrong.

Architecture

Four pieces and no separate knowledge base: everything the assistant knows about me fits in its context.

Dependency-free JavaScript

Browser

The chat panel sends the question, runs the actions the server returns and shows under the answer which one it ran.

Vercel

Serverless function

Validates the request, applies the usage limits, calls the model and returns the answer with a list of actions.

Upstash Redis

Store

Keeps count of the usage limits and stores the questions, without identifying anyone, for 30 days.

Groq

Language model

Receives the rules, my data and the question. It answers in text and, when appropriate, requests an action through a tool call.

Design decisions

Knowledge comes from the same data as the site

The text the model receives is generated on every deployment from the files that render this page. So it can't contradict what you see, and there is no second copy to maintain.

A single model call per question

The provider's free quota is the scarce resource. With one tool and a compact context, each question costs the minimum and the assistant handles more conversations.

Actions against a closed list

The model executes nothing: it proposes an action and the server maps it to a fixed set of values. The browser validates it again before doing it. Anything that doesn't fit is discarded. Every action that runs is shown under the answer, so you can see what the model asked for.

Answers as plain text

What the model writes is never interpreted as HTML, so it can't inject content into the page.

If it isn't configured, it doesn't appear

Without the provider's keys the server says so and the button is not shown. The site works the same with or without the assistant.

Security

  • The provider's key lives only on the server; the browser never sees it.
  • There is a limit of questions per visitor and a global one. If the limits store fails, the model is not called.
  • The assistant's rules are kept separate from the visitor's text, which is trimmed and cleaned before being sent.
  • When someone tries to change its instructions, steer it to other topics or extract internal data, it declines.

How I test it

At two levels. Automated server tests with the model and the store simulated: validation, limits, actions outside the list, provider errors, and that nothing improper is stored. And a battery of questions against the real model with an expected result: correct facts, questions with no answer on the site, manipulation attempts, unrelated topics and the use of each action.

A language model is not deterministic: a passing battery does not guarantee the next answer. That is why the important rules also live in the code that validates what the model returns, as well as in its instructions.

Limits I know about

  • It runs on a free tier: if it gets many questions in a short time, it asks you to wait or points you to the contact form.
  • It can be wrong or misunderstand a request. For anything important, write to me.
  • It depends on a single model provider, although switching to another compatible one is a matter of configuration.

Privacy

What happens to what you type into the assistant.

Controller
Ismael Parras Resino. You can write to me through the contact form or at the email shown on this site.
What is processed
The text of your question, to answer it and to improve the assistant.
What is stored
The day, the language, the text of the question and whether it was answered, for 30 days. Your IP address, your browser and the answers are not stored. The IP is used only briefly, turned into an identifier that cannot be reversed and expires in about a day, to limit usage.
Who else is involved
Groq generates the answer; it is a United States company and your question may be processed outside the European Union. Upstash hosts the database (Dublin region) and Vercel hosts the site.
Deletion
Questions are not linked to any person. If you typed personal data by mistake, tell me the day and the approximate text and I'll delete it.
Advice
Do not type personal data into the assistant.
